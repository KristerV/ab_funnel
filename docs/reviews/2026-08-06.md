# Gate the funnel on an entry event, and let the app declare step order

Brief for whoever picks this up in `~/code/abtest`. Read `README.md`,
`lib/ab_funnel/services/report.ex` and `lib/ab_funnel/admin_live.ex` first.

Main consumer is `~/code/colt`, which uses `ab_funnel` to measure a narrated A/B
demo deck at `/demo` (two variants: `features`, `solving_emails`).

---

## Problem 1 — everyone holding a cookie is in the funnel, so steps can grow

`Report.funnel/2` buckets *every* event by the visitor's cookie variant. Someone
who signed in on the landing page and never opened `/demo` still holds a
`features` cookie, so they count toward `signed_in` but not `deck_started`.

Real prod data, four people:

```
        event          | people | avg_position
-----------------------+--------+--------------
 signed_in             |      3 |         0.00
 deck_started          |      1 |         0.00
 slide_f_intro         |      1 |         1.00
 slide_f_part_contacts |      1 |         2.00
 ...

                person                | events | started_deck | signed_in
--------------------------------------+--------+--------------+-----------
 1de1c94b-e098-4738-8ab3-f7d9b35a3075 |      1 | f            | t
 7886a12e-dc27-454c-a863-a06df968d926 |      1 | f            | t
 ccfdbfbc-1074-4564-9b6c-94c99ce61aef |      1 | f            | t
 6e6b0bd6-4582-4e7e-bd8a-e2da9db997c3 |     50 | t            | f
```

The dashboard renders `Deck started 1 → Signed in 2 → Slide f intro 1` — a
"200%" step conversion. Three of the four people never entered the funnel at all.

## Problem 2 — step order is inferred, and the inference is degenerate here

`Report.step_order/1` (report.ex:59) orders steps by each event's *average
first-touch index* across the people who reached it. For events that only ever
fire inside one linear journey that works. `signed_in` is fired by colt's auth
controller entirely outside the deck, so its position is arbitrary.

In the data above `signed_in` and `deck_started` both average **0.00**. It is a
tie, broken by whatever order `Enum.group_by` happened to emit. There is nothing
to fix in the averaging — it is the wrong mechanism for this shape of data.

Two further consequences of inference:

- `step_order/1` is computed **once, globally**, then applied to every variant.
  Both decks' `deck_started` / `slide_cta` / `deck_completed` positions are
  averaged together into one number. Latent bug.
- A step nobody reached simply **vanishes from the chart**. You cannot see the
  drop-off, which is the one thing the chart exists for.

## The app already has a funnel definition

`ColtWeb.Deck.Slides.order/1` in colt returns an ordered
`[:f_cover, :f_intro, :f_part_contacts, …, :cta]` per variant, and
`deck_live.ex:334` tracks each slide as `"slide_#{key}"`. That is a declared,
per-variant funnel sitting right there. Use it instead of guessing.

## Proposed change

Two config keys, both optional, both defaulting to today's behaviour so no other
app breaks.

```elixir
config :ab_funnel,
  entry_event: "deck_started",
  steps: {Colt.ABVariants, :funnel_steps, 1}
```

### `entry_event`

A person is in the funnel only if they fired it. In `funnel/2`, after
`resolve_people/2` and **after `source_lookup/1` is built** (source events fire
on first landing, before entry — the lookup must see the untrimmed list):

1. Find each person's *first* `entry_event` timestamp.
2. Drop every person who has none.
3. Drop each remaining person's events from *before* that timestamp.

Feed the trimmed list to both the ordering and the counting. Falls out for free:

- the entry event is index 0 for everybody, so it is always the first card
- a pre-deck `signed_in` disappears; only sign-ins *during* the deck count
- no step can exceed the entry count, so >100% becomes impossible

`entry_event: nil` (default) keeps current behaviour.

### `steps`

An MFA `{Module, :fun, 1}` taking a variant string and returning an ordered list
of event names, or `nil` to fall back to inference for that variant.

- `step_order` moves **inside** the per-variant loop and takes the variant.
  Declared list → `%{event => index}`; no list → today's averaging. This also
  fixes the global-averaging bug noted above.
- Events not in the declared list are dropped from that variant's chart, so
  `signed_in` leaves the deck funnel where it never belonged.
- Steps in the list that nobody reached render with count **0** instead of
  vanishing. This is the real payoff — `AdminLive` needs to handle 0-count cards
  and 0% rates without dividing by zero.

Colt side (`lib/colt/ab_variants.ex`), for reference — do not edit colt as part
of this task unless asked, but the shape the library must support is:

```elixir
def funnel_steps(variant) do
  slides =
    variant
    |> ColtWeb.Deck.Slides.order()
    |> Enum.reject(&ColtWeb.Deck.Slides.cover?/1)
    |> Enum.map(&"slide_#{&1}")

  ["deck_started"] ++ slides ++ ["deck_completed", "cta_clicked", "lead_submitted"]
end
```

(The cover slide is never tracked — `track_current_slide/1` first runs after
`start` has already moved the index to 1.)

## Out of scope

**Multiple concurrent A/B tests.** `AbFunnel.Plug.Visitor` sets a single
`ab_funnel_variant` cookie from a single `variants_module().random_key()`, and
`ab_funnel_events.variant` is one string column — "which variant is this person
in" is a global, one-dimensional fact about the browser. Running two tests today
means declaring the cross-product (`features_short`, `features_long`,
`solving_short`, `solving_long`), which quadruples the arms and the traffic
needed. Making experiments first-class — cookie per experiment, `experiment`
column on events, `experiments/0` replacing `variants/0`, report grouped
experiment → variant → source → steps — is a migration plus a breaking change to
the `AbFunnel.Variants` behaviour. Worth doing when a second test actually
exists, not speculatively.

**Variant attribution.** `canonical_variants/1` gives a person the variant of
their *earliest* event, which after gating may be a pre-entry one. Arguably it
should be the variant at the entry event. Left alone deliberately; flag it if it
starts mattering.

### Re-running the prod diagnostic

Read-only, safe to paste into a prod psql session:

```sql
WITH resolved AS (SELECT COALESCE(i.person_key, e.visitor_id) AS person, e.event, e.variant, e.inserted_at FROM ab_funnel_events e LEFT JOIN ab_funnel_identities i ON i.visitor_id = e.visitor_id WHERE e.event NOT LIKE 'source:%'), first_touch AS (SELECT person, event, min(inserted_at) AS at FROM resolved GROUP BY person, event), positioned AS (SELECT person, event, row_number() OVER (PARTITION BY person ORDER BY at) - 1 AS pos FROM first_touch) SELECT event, count(*) AS people, round(avg(pos)::numeric, 2) AS avg_position FROM positioned GROUP BY event ORDER BY avg_position;
WITH resolved AS (SELECT COALESCE(i.person_key, e.visitor_id) AS person, e.event, e.inserted_at FROM ab_funnel_events e LEFT JOIN ab_funnel_identities i ON i.visitor_id = e.visitor_id WHERE e.event NOT LIKE 'source:%') SELECT person, count(*) AS events, min(inserted_at) AS first_seen, bool_or(event = 'deck_started') AS started_deck, bool_or(event = 'signed_in') AS signed_in FROM resolved GROUP BY person ORDER BY first_seen;
```
